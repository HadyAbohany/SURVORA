# Extending NOVA knowledge

The bundled NASA-attributed Markdown is curated secondary material. The registry records source references. The runtime loads per-file metadata from simple Markdown frontmatter. Gameplay design files are a separate layer and describe proposed mechanics.

1. Review the primary source and write or normalize a reference with its provenance. For local static references, place UTF-8 Markdown in `data/nasa` and use `source_id`, `title`, `source_url`, `content_type`, and optional `mission_ids` (comma- or space-separated), `publication_date` and `document_version`. Choose stable source IDs.
2. For another static format, implement `SourceAdapter.load()` in `app/knowledge.py` to yield `Document` values. Register it in the default adapter list in `make_chunks`, or inject it directly in tests. Validate types, URLs and provenance at the source boundary.
3. Add headings around complete ideas. The chunker preserves section boundaries and packs paragraphs up to 1,000 characters. Empty, unreadable and duplicate local bodies are skipped. The index loads from the corpus on restart, so replacing or removing a source removes its old chunks from serving.
4. BM25 builds in memory. Optional Chroma uses a collection fingerprint of embedding model name and chunk IDs. Restart after updates. The old collections remain intact and can be archived by the operator. Pin the model revision externally for reproducible embeddings. Optional semantic ranking and index reload require validation in the target environment.
5. Test source-specific retrieval using a synthetic local adapter fixture. Assert source IDs and compare mission-tagged and untagged queries. Start with BM25. Benchmark a representative query set before enabling hybrid retrieval.

Keep live data in a separate adapter or cache. Normalize records into timezone-aware `Observation` values with the original observation time, retrieval time and source URL. Check freshness against a source-specific policy before use. The supplied observation type validates temporal ordering. The DONKI and ISS DosTel adapters in `app/observations.py` fetch explicitly requested windows. Chat does not fetch or inject these records. See [NASA_DATA_INVENTORY.md](NASA_DATA_INVENTORY.md) for the selected sources and limits. When adding one, put its validated records in a separate reference layer and keep engine rules responsible for any simulated effects. A real space-weather observation alone does not determine the current in-game radiation level.
