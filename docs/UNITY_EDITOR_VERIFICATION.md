# NOVA Unity Editor verification

The available package contains `unity/NovaBridge.cs`. A playable SURVORA Unity project, its scenes and an installed Unity Editor were not located in the accessible project folders. The live HTTP simulation does not verify Unity compilation, event-bus wiring or rendering.

1. Open the actual SURVORA project in the Editor version listed in its `ProjectSettings/ProjectVersion.txt`. Merge `unity/NovaBridge.cs` into the game's existing bridge location. Resolve any duplicate class definitions. Confirm TextMesh Pro is available, clear compilation errors, and check the Console.
2. Open the playable M02 scene and select the NOVA object. Confirm its Inspector has a `NovaBridge`, an assigned TMP subtitle, `http://127.0.0.1:8000` as the Editor backend URL, and an empty session field for a generated per-play session ID. Leave the client token blank for an unauthenticated local server. Check that the scene wiring survives entering Play Mode.
3. Start the backend with the existing server-side Gemini configuration. Confirm `/health` shows the expected model. Route the real engine event bus to `PublishEvent` with the actual event type, mission ID, priority, snapshot and increasing state revision. Bind the Ask/Explain/Hint UI to `Ask` using the current snapshot, authorized action labels and hint level.
4. In Play Mode, enter M02, drive the actual oxygen and power systems below their configured thresholds, then recover and complete the mission. Record the corresponding mission-start, low oxygen, recovery and completion subtitles. Stop the backend and repeat the urgent event. It should still appear immediately. Verify the Uvicorn access log has no request from `PublishEvent`.
5. Restart the backend. Use Ask/Hint with the real in-game snapshot at hint levels 0, 1, 2 and 3. Confirm responses appear in the subtitle and that the game applies no resource or action changes until the player acts. Test one MOXIE question and check the Gemini response and its citation in the backend response.
6. Trigger two asks in quick succession and make their responses arrive out of order using a delayed local test server. Confirm only the newer reply appears. During a delayed ask, advance the state revision and trigger an urgent event. Confirm the old reply and subsequent optional messages do not replace the urgent subtitle during its display window.
7. Repeat an optional event during its cooldown, send an out-of-order revision, and test with the backend stopped during Ask. Verify cooldown suppression, stale-event rejection and a readable fallback. Check the Unity Console for exceptions.
8. Verify the actual target build separately if it runs on another device. Device loopback refers to the device itself. Configure the actual reachable backend or relay endpoint. The bundled Unity bridge sends English. Arabic was exercised through the HTTP API. If the game supplies its own Arabic UI integration, additionally verify glyph coverage, shaping and right-to-left layout in that UI.
